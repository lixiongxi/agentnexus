# AgentNexus 界面重开发方案 · 10 轮独立深度推演

> 推演对象：`agent-hub/index.html`（单文件应用，重构前 1570 行：CSS 238 行 / HTML 外壳 68 行 / JS 1252 行）
> 推演方法：每轮**独立**锁定一个维度，按「诊断（事实）→ 论证（因果）→ 结论（判断）→ 改进点（可执行）」四步输出，互不预设结论；第 11 章将 10 轮结论交叉求交，输出综合最优方案。
> 约束条件：不破坏既有业务契约（12 项前端回归断言必须全绿）、不引入构建工具、保持单文件可分发。

---

## Round 1 · 信息架构与导航范式

**诊断**
- 6 个一级页面（我的 Agent / AI 伙伴 / 广场 / 会话 / 人脉 / 协议）平铺于侧栏，无主次之分，但使用频次差异显著（广场、会话为高频）。
- 移动端 ≤900px 直接 `.sidebar{display:none}`，**导航整体消失**，用户无任何替代入口——这是架构级缺陷而非样式问题。
- 侧栏底部「演示说明」静态文案占据一级导航区，与导航功能混杂。

**论证**
导航是信息架构的骨架。移动端直接隐藏导航，等价于剥夺了用户在小屏上的全部页面间跳转能力，属于"降级即残废"。同时，6 项平铺导致视觉权重均分，高频入口无法被快速定位。但需注意：本产品为低频切换的深度工作台，盲目改为"底部导航优先"会牺牲侧栏可承载的说明性内容。因此最优解是**分层而非替换**——桌面保留侧栏（承载主导航+说明），移动端用抽屉保留完整信息，另设底部标签栏承载高频切换。

**结论**
采用「侧栏（信息完整）+ 底部标签栏（高频快捷）」双通道，按屏宽互斥激活；侧栏在移动端转为抽屉，导航能力零丢失。

**改进点**
1. 新增 `.tabbar` 底部标签栏（≤1024px 激活），6 项与侧栏共用 `.nav-item[data-page]`，复用既有事件绑定。
2. 侧栏 ≤1024px 由 `display:none` 改为 `transform:translateX(-100%)` 抽屉 + `body.nav-open` 状态驱动。
3. 新增 `#nav-overlay` 遮罩，`toggleNav()/closeNav()` 控制，点击遮罩与 Esc 均可关闭。
4. 侧栏导航项点击后自动收起抽屉（捕获阶段监听，先于业务 handler）。
5. 说明性文案降级为 `nav-tag` + 小字，与导航项视觉分离。

## Round 2 · 视觉设计系统与设计令牌

**诊断**
- 令牌仅 16 个 CSS 变量，缺中性色阶、语义色、间距、圆角、阴影、动效的成体系定义；`--radius:14px`、`--shadow` 为单值，无法分层。
- 文字色 `--ink3:#8B94A8` 白底对比度实测 **≈3.0:1**，低于 WCAG AA 要求的 4.5:1（该色承载了 `.section-desc`、`.o-org`、时间戳等大量正文级信息）。
- 全站无暗色模式；`--mono` 字体变量定义后仅 1 处使用。

**论证**
令牌体系决定改造成木。单值 `--radius` 使得卡片、按钮、气泡、头像的层级关系无法表达；对比度不足的辅助文字在小字号（11–12px）下可读性进一步恶化。将色彩重写为「中性色阶 + 语义色 + 状态色」三层，并用 4pt 基准间距与分层阴影，可在不改动任何 JS 的前提下整体提升品质——这是**投入产出比最高**的一轮。

**结论**
重建为 5 层令牌（色彩/间距/圆角/阴影/动效），全部文字色通过 AA 校验，并补齐暗色主题。

**改进点**
1. 文字色重写并校验对比度：`--ink` 17.4:1 / `--ink-2` 7.5:1 / `--ink-3` **4.7:1（AA 通过）**，替代原 3.0:1。
2. 补齐中性色阶（`--surface` / `--surface-2` / `--surface-3` / `--line` / `--line-2`）。
3. 语义色拆分为主色 + soft 底色（`--green/-soft`、`--amber/-soft`、`--red/-soft`、`--cyan/-soft`）。
4. 新增 4pt 间距尺（`--sp-1`…`--sp-12`）、圆角尺（`--r-xs`…`--r-full`）、5 级阴影（`--elev-0`…`--elev-4`）。
5. 新增 `[data-theme="dark"]` 完整暗色令牌；`<head>` 内前置脚本按系统偏好/本地存储预置主题，消除 FOUC 闪白。
6. 语义色值微调以通过暗底对比（如 `--green:#34D399`、`--red:#F87171`）。

## Round 3 · 布局与栅格系统

**诊断**
- 会话页与伙伴页高度使用硬编码 `calc(100vh - 150px)` / `calc(100vh - 200px)`，与 topbar（60px）+ padding（48px）耦合；移动端浏览器工具栏伸缩时会被裁切。
- 容器宽度 `.page{max-width:1100px}` 固定，1440px+ 屏幕两侧留白过大，1280px 以下又无收敛。
- `.grid2/.grid3` 在 ≤900px 才塌缩为单列，1024–900px 区间出现三列挤压。

**论证**
`100vh` 在移动端包含被隐藏的地址栏高度，导致内容超出可视区——这是移动端最经典的布局缺陷。应改用 `dvh`（动态视口高度）并以 `vh` 兜底。容器宽度应随断点收敛而非固定值。栅格塌缩点前移至 1024px 与侧栏变抽屉的断点对齐，避免"侧栏已变成抽屉、主区却仍是三列挤压"的中间态。

**结论**
高度改用 `clamp() + dvh` 双层兜底；容器宽度令牌化并随断点调整；栅格塌缩点与导航断点统一为 1024px。

**改进点**
1. `.chat-layout` / `.buddy-card` 高度改为 `clamp(420px, calc(100dvh - 108px), 900px)`，前置 `vh` 版本作兼容兜底。
2. 新增 `--container` 令牌：默认 1120px，≥1440px 放宽至 1240px 且加大页面内边距。
3. `.grid2/.grid3` 塌缩断点由 900px 前移至 1024px，与抽屉断点对齐。
4. `.agent-grid` 最小卡片宽度 260px→220px（平板）、单列（手机），避免窄屏挤压。
5. 为长列表容器添加 `contain:layout style` 以隔离布局计算。

## Round 4 · 组件一致性与复用

**诊断**
- 同类交互存在多套实现：可切换标签有 `.tag-pick .t`、`.filter-row .f`、`.radio-row .r` 三套，hover/选中态视觉语言不统一。
- `.btn` 存在 `!important`（`.btn:disabled{transform:none!important}`），暗示状态管理有副作用。
- 头像存在 `.ava-lg`、`.ava`、`.owner-mini .ava`、`.avatar-stack .ava`、`.top-ava` 多套尺寸，无统一尺阶。
- 无骨架屏（skeleton），异步加载期间为空白。

**论证**
组件分化的根因是「按页面写样式」而非「按组件写样式」。三套标签选择器虽外观相近，但圆角、内边距、hover 行为各不相同，维护者修改其一必然遗漏其余。统一不等于合并 DOM（会破坏 JS 契约），而是**统一视觉语言**：共用相同的圆角、过渡时长、选中态配色与 focus 表现。

**结论**
保留既有类名与 DOM 结构（避免破坏 JS 与回归测试），通过统一令牌与状态样式实现视觉一致性；补齐骨架屏。

**改进点**
1. 三套标签/筛选器统一为相同圆角（`--r-full`）、过渡（`--dur-1 var(--ease)`）、选中态（品牌色填充 + 阴影）。
2. 移除 `:disabled` 的 `!important`，改用更精确的选择器顺序。
3. 头像尺寸归纳为 26/28/32/34/38/40/48/72px 明确的尺阶，全部使用 `--r-*` 令牌。
4. 新增 `.skeleton` 骨架屏组件（shimmer 动画），供异步列表占位。
5. 新增 `.btn-block`、`.chip.red`、`.card-hover` 等补齐型工具类。

## Round 5 · 交互反馈与微动效

**诊断**
- 页面切换仅有 `fadeIn .25s`，卡片 hover 使用 `transform:translateY(-3px)` 但无 `:active` 态，触控无按压反馈。
- 全局搜索 `oninput` 直接触发 `render()`——**每输入一个字符即全量重建 DOM**，长列表下明显卡顿。
- `#chat-dot` 未读红点定义了 DOM 与样式，但**全代码库无任何 JS 切换它**，是死代码。
- Toast 无堆叠上限，连续触发会溢出视口。

**论证**
交互反馈的价值在于「确认操作已生效」与「告知系统状态」。缺失 `:active` 态会让触控用户不确定是否点中；逐字全量重渲染是典型的输入性能反模式（应防抖 150–300ms）。死代码红点不仅是冗余，更意味着"未读"这一重要状态实际上对用户**完全不可见**——这是功能缺失而非仅是代码整洁问题。

**结论**
补齐按压态、防抖搜索、真实未读角标，并统一动效时长/曲线令牌。

**改进点**
1. 为 `.nav-item`、`.btn`、`.agent-card`、`.switch` 等补齐 `:active` 态（轻微 scale/位移）。
2. 搜索输入改为 `onGlobalSearchDebounced`（220ms 防抖），保留原 `onGlobalSearch` 供既有调用。
3. **修复死代码**：新增 `syncUnreadDots()`，包装 `renderNav` 后同步侧栏 `#chat-dot` 与标签栏 `#chat-dot-tab`，使未读状态真实可见。
4. Toast 容器加 `pointer-events:none`、`max-width:calc(100vw - 32px)` 防溢出。
5. 统一动效令牌：`--ease` / `--ease-out` / `--dur-1~3`，页面入场改为 `pageIn`（位移+淡入，340ms）。
6. 新增 `prefers-reduced-motion` 全局降级，尊重系统减弱动效偏好。

## Round 6 · 响应式与多端适配

**诊断**
- 全站仅 1 个断点（`@media(max-width:900px)`），且内容仅为「隐藏侧栏 + 单列 + 隐藏 api-badge」。
- 无平板（768–1024px）专项适配；无触控设备适配；未处理刘海屏安全区（safe-area）。
- 模态框在移动端仍是居中卡片，未利用底部抽屉式（bottom sheet）这一移动端更顺手的形态。

**论证**
响应式不是"把桌面版压缩"，而是按输入方式（指针 vs 触控）与视口尺寸重新组织信息密度。单一断点必然在中间尺寸出现半成品态。触控设备需保证 ≥44px 的可点击区（iOS HIG / Android Material 共识），否则误触率显著上升。

**结论**
建立 5 档断点（1440 / 1280 / 1024 / 768 / 480）+ `pointer:coarse` 设备适配 + 安全区内边距；移动端模态改为底部抽屉。

**改进点**
1. 断点体系：`≥1440`（放宽容器）、`≤1280`（收紧搜索框）、`≤1024`（抽屉+标签栏+栅格单列）、`≤768`（模态转 bottom sheet、hero 纵向、搜索换行）、`≤480`（精简边距与字号）。
2. 新增 `@media (pointer:coarse)`：图标按钮 44px、按钮最小高度 40px、开关加大至 50×28px。
3. 抽屉与标签栏使用 `env(safe-area-inset-top/bottom)` 适配刘海屏。
4. 移动端 `.modal` 改为底部 sheet（`border-radius` 上圆角 + `sheetIn` 上滑动画），`.modal-foot .btn` 等分宽度便于拇指点击。
5. 会话页移动端改为纵向单栏（列表限高 180px 置顶 + 会话区自适应高度）。

## Round 7 · 可访问性（a11y）

**诊断**
- 无 `:focus-visible` 焦点样式（原 `input:focus` 仅改边框色），键盘用户无法判断焦点位置。
- 无跳转链接（skip link）、无 `lang` 之外的语义标签（侧栏/主区/导航均为 `div`）。
- 图标按钮（通知、头像）无 `aria-label`；装饰性 SVG 未标 `aria-hidden`。
- 色彩对比度未达 AA（见 Round 2）。

**论证**
a11y 改造成本极低但收益明确：焦点环与 aria 标签不影响视觉呈现，却使键盘与读屏用户可用。需要注意的是，全局 `:focus-visible` 必须仅对键盘生效，否则鼠标点击会残留难看的轮廓——这正是 `:focus-visible`（而非 `:focus`）的设计目的。

**结论**
补齐焦点管理、语义化标签、ARIA 属性与跳转链接，全部视觉不影响。

**改进点**
1. 全局 `:focus-visible` 焦点环（2px 品牌色 + 2px offset），`:focus{outline:none}` 避免鼠标点击残留。
2. 新增 `.skip-link`（默认移出视口，聚焦时滑入），支持键盘直达主内容。
3. 语义化：`<aside>` / `<header>` / `<main>` / `<nav>` 替代无意义 `div`；`#view` 加 `tabindex="-1"` 使跳转可聚焦。
4. 所有图标按钮补 `aria-label`；装饰 SVG 统一 `aria-hidden="true"`；`.pop` 加 `role="dialog"`。
5. 菜单按钮加 `aria-expanded` / `aria-controls`，由 JS 同步开合状态。
6. 搜索框加 `aria-label` 与 `type="search"`。

## Round 8 · 渲染性能

**诊断**
- 搜索逐字触发 `render()` 全量重建（Round 5 已述），是最主要的性能瓶颈。
- `render()` 每次重建整个 `#view.innerHTML`，长列表（广场数十张卡片）下无虚拟滚动或分片。
- 无 `content-visibility` / `contain` 等 CSS 渲染提示。
- 动画使用 `transform/box-shadow`（`box-shadow` 动画会触发重绘）。

**论证**
在单文件、无框架的场景下，最有效的性能手段是「减少重建次数」而非引入虚拟滚动（后者复杂度与风险不成比例）。防抖解决了输入侧最高频的重建。CSS 层面，`contain:layout style` 可将卡片的布局计算隔离，浏览器无需因单卡变化重算整个网格；`content-visibility` 对屏幕外内容跳过渲染，适合长列表。二者均为低成本高收益。

**结论**
以「防抖 + CSS 容器隔离」为主，不引入虚拟滚动；避免动画 `box-shadow` 等非合成属性。

**改进点**
1. 搜索防抖 220ms（同 Round 5）。
2. `.agent-card` 添加 `contain:layout style`。
3. 卡片 hover 的 `box-shadow` 与 `transform` 已属合成友好属性，保留但缩短时长。
4. 自定义滚动条（`-webkit-scrollbar` + `scrollbar-width`），避免系统滚动条引发布局跳动。
5. 预留 `.skeleton` 供未来接入异步列表，避免加载期布局抖动（CLS）。

## Round 9 · 空状态 / 边界与内容策略

**诊断**
- 已有 `.empty-state`（广场无结果、会话为空等），但缺少加载态与错误态。
- 长文本（Agent 简介、消息气泡）无换行保护，超长英文/URL 会撑破卡片。
- 侧栏「演示说明」文案与产品口吻不一致（"均为本地模拟"，但实际已支持真实后端）。

**论证**
边界状态决定产品的完成度感知。用户遇到空白页时若无法判断是"加载中"还是"真的没有数据"，会产生困惑。文本溢出是内容驱动型界面最易被忽视的崩溃点——一个长 URL 即可破坏整行布局。

**结论**
补齐加载/空/错误三态，强化文本溢出保护，修正过时文案。

**改进点**
1. 新增 `.skeleton` 骨架屏作为加载态（`shimmer` 动画）。
2. 消息气泡加 `word-break:break-word; overflow-wrap:anywhere`，杜绝长串撑破。
3. `.a-name`、`.o-name`、`.ci-name` 等加 `text-overflow:ellipsis` 单行截断。
4. `.a-role` 设 `min-height:2.6em` 使卡片高度在网格中对齐，避免瀑布式参差。
5. `.msg` 最大宽度按断点放宽（78%→88%→92%），小屏更充分利用宽度。
6. 保留并统一 `.empty-state` 三档间距（小屏减小 padding）。

## Round 10 · 可维护性与工程化

**诊断**
- 单文件 1570 行，CSS 集中在前 238 行，无分区注释（原仅有若干 `/* ===== */` 分隔）。
- 样式与 JS 生成的 HTML 强耦合（JS 内大量内联 `style="..."` 与模板字符串），改样式需同时理解 JS。
- 无测试覆盖新增交互；既有测试仅覆盖渲染不崩溃。
- 无构建/格式化工具，靠人工维护。

**论证**
可维护性的核心是「降低认知负荷」与「提高变更安全感」。在保持单文件可分发的前提下，最务实的做法是：① 用令牌取代魔法数字，使主题/间距调整集中化；② 为 CSS 建立清晰分区与注释；③ 为新增交互补自动化测试，使后续重构有护栏。强行拆分为多文件会丧失"单文件即可部署演示"这一该项目的核心优势（CloudStudio 静态部署依赖此特性），**不应拆分**。

**结论**
保持单文件架构；以令牌化 + 分区注释 + 测试覆盖提升可维护性；新增交互全部纳入自动化测试。

**改进点**
1. CSS 重排为 11 个编号分区（令牌 / 暗色 / 重置 / 布局 / 组件 / 各页面 / 浮层 / 响应式），每区带标题注释。
2. 全面令牌化：消除硬编码色值与尺寸，主题切换仅需覆盖 `:root` 变量。
3. 新增 `scripts/ui-enhancement-test.cjs`（14 项断言）覆盖抽屉、主题、防抖、未读角标、a11y 结构。
4. `package.json` 新增 `test:ui` 与 `test:all` 脚本，与既有 `test:frontend` 串联。
5. 保留完整备份（`.uibuild/index.backup.html`）与可复现的构建脚本（`.uibuild/build.mjs`），拼接前做锚点行校验，失败即中止。
6. 补充 `@media print` 打印样式，隐藏导航与输入区。

# 11 · 综合最优方案（最终交付）

## 11.1 十轮结论交叉汇总

| # | 维度 | 核心结论 | 关键量化收益 |
|---|------|----------|--------------|
| 1 | 信息架构 | 侧栏 + 底部标签栏双通道，移动端抽屉 | 移动端导航能力 **0 → 完整**（原直接隐藏） |

## 11.2 架构决策与权衡

| 决策 | 选择 | 被否决方案 | 理由 |
|------|------|-----------|------|
| 文件组织 | **保持单文件** | 拆分为 index.html + css + js | 单文件是 CloudStudio 静态部署与离线演示的核心前提 |
| 移动端导航 | **抽屉 + 底部标签栏** | 仅汉堡抽屉 / 仅底部栏 | 抽屉保留完整信息，标签栏满足高频切换，二者互补 |
| 组件改造 | **保留类名，改样式** | 重写 DOM 结构 | 重写会破坏 JS 契约与 12 项回归断言，收益不抵风险 |
| 高度计算 | **`clamp() + dvh`** | JS 动态注入 `--vh` | 纯 CSS 方案无 JS 运行时开销，且 `vh`/`dvh` 双层兜底 |
| 暗色模式 | **跟随系统 + 可切换** | 仅手动切换 | 尊重系统偏好，`<head>` 前置脚本消除 FOUC |
| 虚拟滚动 | **不引入** | 长列表虚拟滚动 | 当前数据量（十余个 Agent）收益远低于复杂度与风险 |
